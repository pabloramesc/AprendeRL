# Quantile Regression DQN (QR-DQN)

[Back to the algorithm index](../algorithms.md)

**Policy classification:** Off-policy. QR-DQN trains on uniformly replayed
transitions generated by an epsilon-greedy behavior policy.

**Use when:** observations are numeric `Box` vectors or tensors, actions are
`Discrete`, and a distributional value estimate is desired without selecting a
fixed range of possible returns as C51 requires.

## Fixed quantile representation

QR-DQN approximates the return distribution with `quantiles` equally weighted
locations. Their fixed quantile fractions are the midpoints

$$
\tau_i=\frac{i+\tfrac12}{N},\qquad i=0,\ldots,N-1.
$$

The network directly predicts the corresponding return values
$\theta_i(s,a)$. Unlike C51, these outputs are values rather than logits or
probabilities, and they are not constrained to a fixed value support. Their
arithmetic mean gives the action value:

$$
Q_\theta(s,a)=\frac{1}{N}\sum_{i=0}^{N-1}\theta_i(s,a).
$$

The default `QuantileQNetwork` flattens observations, applies two 128-unit ReLU
layers, and returns shape `(batch_size, action_count, quantiles)`.

## Target quantiles

The next action maximizes the mean predicted return. The target network selects
that action by default; setting `double_dqn=True` makes the online network
select it instead. In both cases, the target network provides its $N$ quantile
values for the selected action:

$$
y_j=r+\gamma(1-d)\theta^-_j(s',a^*).
$$

Here $d=1$ only for Gymnasium `terminated`; time-limit `truncated` transitions
continue to bootstrap. Replay timing, hard target updates, epsilon decay,
gradient clipping, and Adam optimization follow the shared
[DQN implementation](dqn.md).

## Quantile Huber loss

Every predicted quantile is compared with every target quantile. For error
$u_{ij}=y_j-\theta_i(s,a)$ and threshold $\kappa$, define

$$
H_\kappa(u)=
\begin{cases}
\tfrac12u^2, & |u|\leq\kappa,\\
\kappa(|u|-\tfrac12\kappa), & |u|>\kappa.
\end{cases}
$$

The asymmetric quantile weight penalizes under- and overestimation differently:

$$
\rho_{\tau_i}^{\kappa}(u_{ij})=
\left|\tau_i-\mathbf 1\{u_{ij}<0\}\right|
\frac{H_\kappa(u_{ij})}{\kappa}.
$$

AprendeRL averages $\rho$ over every batch item and all $N^2$ predicted-target
pairs. `huber_threshold` is $\kappa$ and defaults to `1.0`.

## Usage

```python
import gymnasium as gym

from aprenderl import QRDQN, QRDQNConfig

env = gym.make("CartPole-v1")
config = QRDQNConfig(
    quantiles=51,
    huber_threshold=1.0,
    buffer_size=20_000,
    learning_starts=1_000,
    double_dqn=True,
)
agent = QRDQN(env, config=config).learn(20_000)

agent.save("qr_dqn.pt")
restored = QRDQN.load("qr_dqn.pt", env)
```

A custom `network` must accept an observation batch and return quantile values
with shape `(batch_size, action_count, quantiles)`. Loading a checkpoint made
with a custom network requires the same architecture through `network=...`.

The algorithm and loss helper are in
[`src/aprenderl/algorithms/qr_dqn.py`](../../src/aprenderl/algorithms/qr_dqn.py),
and the default network is in
[`src/aprenderl/networks/distributional.py`](../../src/aprenderl/networks/distributional.py).
See the runnable [`QR-DQN example`](../../examples/qr_dqn.ipynb) and the
standalone [`QR-DQN study notebook`](../../study/05_distributional_rl/02_qr_dqn.ipynb).
